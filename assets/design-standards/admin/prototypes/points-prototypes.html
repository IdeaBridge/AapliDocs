Grouped table

Today's table, tidied up.

What changes

  • Request and Response become section rows, each task a band, actions underneath, so there are no merged cells.
  • Columns are grouped: People on the record, then Workflow task assignees.
  • Task columns are added with "+ Task" and removed with the × in their header.
  • The /T prefix becomes a share toggle beside the number. It's stored as /T as before.
  • Numbers are right-aligned; zero shows faded.

Good for

  • Seeing every value at once.
  • Smallest change to build.

Watch out

  • Gets wide once several task columns are added.

Action list + panel

The same pattern as Features, Other settings and Users.

What changes

  • Request and Response switch with a toggle, so you only see one workflow at a time.
  • Each action shows who earns points as chips, plus the total.
  • The panel has one labelled field per recipient, each explained.
  • Workflow task assignees are added per action inside the panel, not as table columns.
  • Sharing is a plain checkbox with an explanation; no /T to remember.

Good for

  • Clearest for new admins.
  • Scales to any number of tasks.

Watch out

  • Changing many actions means opening each one.

Cards by task

Follows the workflow: one card per step.

What changes

  • Each workflow task is a card that folds; its header shows how many points the step gives in total.
  • Inside, each action is a row with an input per recipient.
  • A summary line shows the most a creator, team member and assignee can earn across the workflow.
  • Task-assignee points sit on that task's own card, so there are no extra columns.
  • On narrow screens rows stack with labels.

Good for

  • Matches how people think about the workflow.
  • Works on small screens.

Watch out

  • Comparing the same action across tasks needs scrolling.
Suggestion: Option 1 if admins tweak numbers often, as with roles and permissions; Option 3 if it should read like the workflow.
