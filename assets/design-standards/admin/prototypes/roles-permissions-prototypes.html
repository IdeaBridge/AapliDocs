Grouped matrix

Keeps today's table, but makes it readable.

What changes

  • Columns are grouped: Records, Lifecycle, Output and Social.
  • Roles are grouped by type: Default, Custom, then Workflow tasks.
  • The "all roles" row is labelled, and the role column stays put when you scroll sideways.
  • Hovering a cell highlights its column.
  • Permissions a role can't have show a dash, not a greyed tick.
  • "Add role" opens a picker; each row's ⋮ removes the role.

Good for

  • Comparing roles at a glance.
  • Smallest change to build.

Watch out

  • Still wide; on a laptop it scrolls sideways.

Role list + panel

The same pattern as Features, Other settings and Users.

What changes

  • Each role is a row showing its access level and how many permissions it has.
  • Selecting a role opens a panel with switches grouped into cards, each with a short explanation.
  • Quick presets set the switches in one click: Read only, Contributor, Manager.
  • Rules are explained in place, e.g. "Workflow task roles can't add records".

Good for

  • Consistency with the rest of the console.
  • Room to explain each permission.
  • Works on narrow screens.

Watch out

  • Comparing two roles means opening each one.

Access levels per role

Turns the table round: roles across the top, permissions down the side.

What changes

  • There are usually far fewer roles than permissions, so the table fits the width.
  • The first row sets an access level per role: None, Read only, Contributor, Manager or Custom.
  • Permission groups fold away; their header shows a count for each role.
  • Changing a single tick switches that role to Custom.
  • Each permission has a one-line description.

Good for

  • Fast set-up: most apps only need the level row.
  • Comparing roles side by side.

Watch out

  • Needs agreed preset definitions; the backend still stores individual ticks, so no API change.
Suggestion: Option 3 if admins mostly set up new apps; Option 2 if you want it to match the rest of the console.
