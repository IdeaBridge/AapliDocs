A · Row menu

A ⋮ button is always on every row. Selecting rows swaps the toolbar for bulk actions.

Good for

  • Tables with many actions per row (Users has 6)
  • Dense lists admins scan, then act on one row
  • Bulk work: suspend or export 30 people at once

Trade-offs

  • Every action is two clicks
  • Actions are hidden until the menu opens, so new admins discover them by trying

Rules it would add

  • ⋮ always visible, 32px, with the aria-label "Actions for {name}"
  • Destructive items last, in red, after a divider, then a confirmation step
  • Checkbox column only where bulk actions exist

Recommended default for most admin tables (Users, Roles, Cards, Announcements).

B · Open in panel

The row has no buttons. Selecting it opens a right-hand panel with the details and every action, the same pattern as Features and Settings.

Good for

  • Records where people look before they act (Failed submissions, Email logs, Import history)
  • Keeping the table calm and readable
  • Consistency with the panels already in the admin

Trade-offs

  • Quick, repeated actions (reset password for five people) take more clicks
  • The panel covers part of the table

Rules it would add

  • The name is a link-styled button; the row shows a › so it reads as openable
  • Panel lists actions in a column, with destructive ones last
  • Bulk actions still come from row selection

Recommended for read-first records and anywhere a row has more detail than the table can show.

C · Visible actions

The one or two most used actions are text buttons on every row; everything else sits in ⋮.

Good for

  • Tables where one action dominates (Edit, Resubmit, Download)
  • Admins who repeat the same action down a list

Trade-offs

  • Busier rows; the action column needs about 220px
  • Choosing which actions get promoted is a product decision per table
  • No bulk selection in this version

Rules it would add

  • At most two visible actions, as text buttons, never icons alone
  • Never a destructive action as a visible button
  • Same action order on every row

Use selectively on tables built around one repeated task, e.g. Failed submissions (Resubmit) or Import templates (Download).
